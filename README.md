# なぜ南武線は混んでるのか？ / NANBU LINE PUZZLE (Ver.0.90)

> **最終更新: 2026年11月27日 ／ 最新バージョン: Ver.0.90**  
> ※ 更新履歴は [**`CHANGELOG.md`**](./CHANGELOG.md) をご覧ください。  
> ※ 本ゲームは実在の鉄道会社様とは一切関係ありません。

走行中の南武線車内（5×8マス）をリアルタイムに並び替え、主要乗換駅の混雑を定時でさばくブラウザパズルゲームです。

---

## 📖 1. 概要

川崎〜立川間（全26駅）の実距離・実乗降傾向をもとに、走行中に乗客をドラッグ／タップで入れ替えてドア前へ繋ぎ、スムーズ降車と定時運行を目指します。

---

## ✨ 2. 主な機能

- **15種類の運行列車**: 下り6種・上り9種（各駅停車／快速／区間運転／朝ラッシュ／終電間際／夜間運行・緩急接続演出に対応）。
- **難易度＆追加難易度**: ダイヤ難易度4種（亀 1.3倍／のんびり 1.0倍／標準ダイヤ 0.8倍／回復運転 0.6倍）と、追加難易度4種（ドア前地蔵／G1開催／ベビーカー／御老人）を自由に組み合わせ可能。
- **車窓アニメーション＆サウンド・BGM**: 駅固有ID＋区間タイムライン方式に連動した上部1面横スクロールの5種類の車窓（街並み／武蔵小杉タワマン／住宅地8割／混在5割／多摩川橋梁）＋昼夜切替、Web Audio API による効果音および2モードBGM（タイトル84 BPM・走行中104 BPMユニゾンシンセ）＋SE/BGM個別音量調整を内蔵。
- **スコア・ハイスコア＆SNSシェア**: 連続ノー詰まりコンボ・定時ボーナス・難易度倍率・最高評価 **SS** に対応。完走スコアの自動記録（総合TOP20／シナリオ別15列車TOP3／全26駅累計輸送実績・選択削除・CSV保存／マージ読込）、リザルト結果コピー＆Xポスト機能、PNGスクショ保存を搭載。

## 📊 3. 乗客データ仕様（交通センサス・丸め処理・例外ルール）

### 3-1. データ出典および利用規約の遵守
- 乗客の流動ベースには、**国土交通省「第13回大都市交通センサス（2021年12月調査・IC定期外）」（e-Stat）** を南武線内相互OD行列（26駅×26駅 有向行列）に加工して使用しています。
- 政府標準利用規約（第2.0版）および e-Stat 利用規約に準拠し、出典を明記したうえで、ゲームプレイ向けに独自加工・調整を加えたデータであることを明示しています（実際の運行・混雑状況とは異なる場合があります）。

### 3-2. ゲーム向け数値変換・丸め仕様（`js/puzzle.js`）
40マス（5行×8列）の盤面で破綻なく遊べるよう、以下の手順で1運行ぶんの乗客を事前生成しています。

1. **べき乗スケーリング（バランス補正）**: 駅ごとの合計乗車数 $B_i$ に $B_i^{\gamma}$（現行 $\gamma = 0.75$）を適用し、乗降の少ない中間駅も適度に乗客が発生するよう圧縮補正。
2. **ピーク断面正規化**: 路線内で最も混雑する区間の期待乗車数が **`35人`**（G1開催時は最大 **`37人`**、ドア前地蔵ON時は固定枠2マスを控除）となるよう全体を線形スケーリング。
3. **確率的丸め（Stochastic Rounding）と最低保証**: 各駅の期待乗車数 $\lambda$ を「$\lfloor \lambda \rfloor$ ＋ 小数部の確率で $+1$」により整数化し、全停車駅で **最低1人以上** の乗車を保証。
4. **40マス定員保証シミュレーション**: 1運行ぶんを最大80回試行し、全区間で車内人数が実定員（40マス）以内に収まるスケジュールを採用。

### 3-3. 例外処理・シナリオ別調整の概要

#### ① 特定列車・駅の最低保証枠（`GUARANTEED_PASSENGERS`）
確率抽選で主要通し客が0人になるのを防ぐため、一部列車では乗車人数 `cnt` の先頭枠として指定着駅の乗客を最低人数ぶん確実に発生させます（例：川崎発 快速 立川行の川崎時点で立川行を固定確保。定員超過なし。全定義は `js/data.js` 参照）。

#### ② シナリオ別の期待乗車倍率調整
時間帯・運行特性を再現するため、一部シナリオ列車では特定駅の期待乗車数に個別倍率を掛けています（例：朝ラッシュ列車での始発駅ブーストや、終電間際列車での途中駅減少補正など。全定義は `js/data.js` 参照）。

#### ③ 快速の緩急接続・乗換集約処理
快速列車では緩急接続駅（例：下り快速の稲城長沼連絡など）において、連絡対象となる通過駅方面の乗客を接続駅への乗換客として合算します。なお、終点より先の着駅を終点行きへ集約するのは終点連絡を持つ快速のみで、その他の区間運転列車では運行区間内の実ODのみから抽選します（詳細は `js/data.js`・`js/puzzle.js` 参照）。

#### ④ 追加難易度設定による例外・制限
- **🗿 ドア前地蔵**（スコア倍率 `+0.25`）：始発時に左右ドア内側2マスへ終点まで移動不可の乗客を固定配置。
- **🏇 G1開催**（スコア倍率 `+0.10`）：府中本町の降車 `×2`・乗車 `×10`（府中本町停車列車のみ有効。朝ラッシュ・夜間列車では選択不可）。
- **👶 ベビーカー**（スコア倍率 `+0.25`）：縦2マス一体移動（最大2セット）。40マス定員保証維持のため同一着駅ペアを優先抽出し、該当がない場合は手前の着駅へ統一。朝ラッシュでは選択不可。
- **👴 御老人**（スコア倍率 `+0.20`）：座席数と同数の最大6人まで出現。朝ラッシュでは選択不可。

## 🚀 4. 動作方法

ビルドやWebサーバーは不要です。**[`index.html`](./index.html) をブラウザで直接開くだけ（`file://`）**、または GitHub Pages 等の静的ホスティングでそのまま動作します。  
※ `file://` 直開き互換のため ES Modules は使用せず、クラシック `<script defer>` と `window.Nanbu*` 名前空間で構成しています。

> [!NOTE]
> **開発・プライバシーに関する注記**
> - 本プロジェクトのコーディングには AI（Gemini）を使用しています。
> - 本ゲームはすべてブラウザ内で完結して動作します。プレイ内容・スコア・スクリーンショット等のデータが外部サーバーへ送信されたり、AIの学習に利用されたりすることは一切ありません。
